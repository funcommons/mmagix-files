> 2026-10-29 · 基于 v1.1.0（commit 6b225b41）代码实测 + TOP3 竞品调研（见《同类项目对比与升级建议》）。
> **红线**：纯前端零后端，S3 预签名直连，凭证不出前端——所有需求细节以该边界可行为准。
> 文件名说明：原需求名「断点上传/分享增强/在线解压/回收站」含 `/` 不合法，以 `-` 代之。

## 0. 现状与目标总览

| 能力 | 大厂基准 | 现状实测（v1.1.0） | 真实差距 | 估时 |
|---|---|---|---|---|
| 断点上传 | OSS checkpoint 断点续传、S3 Multipart | **multipart 已有**：`upload-queue.ts` createMultipart/uploadPart/completeMultipart，pause/resume/retry/abort，会话内 uploadId+parts 续传 | 仅缺**跨会话续传**（刷新即丢）+ 单片重试退避 + 自适应分片 + 进度 + 孤儿清理 | 2.5d |

## 1. 公共底座（M1）

### 1.1 SigV4 预签名支持自定义 query

现状：`sdk/s3/sigv4.ts` 的 `PresignInput` 无 extra query 字段，且 `presignGet/presignPut` 组装时 `url.split('?')[0]` 丢弃已有 query——`versionId`、`partNumber`、`uploadId`、`response-content-disposition` 均无法进预签名（头签名 `signRequest` 通道可签任意 query，仅预签名受限）。

改造（向后兼容，可选字段）：

```ts
interface PresignInput { url; expires; extraQuery?: Record<string, string> }
// canonical query = sort([...X-Amz-* 六项, ...extraQuery]) 合并进规范化请求与签名 URL
```

注意：**Range 请求头不参与签名**（现有 presign `SignedHeaders=host`），预签名 URL 直接带 `Range:` 头可用——在线解压零改造依赖此事实。

### 1.2 client 新增方法（`sdk/s3/client.ts`，全部走头签名通道，零额外签名工作）

| 方法 | S3 语义 | 服务 |
|---|---|---|
| `getBucketVersioning()` | GET `?versioning` | 回收站前置检测 |
| `listObjectVersions({prefix, keyMarker, versionIdMarker, maxKeys})` | GET `?versions` | 回收站/版本历史 |
| `deleteVersion(key, versionId)` | DELETE `?versionId=` | 恢复（删 DeleteMarker）/彻底删除 |
| `listMultipartUploads()` | GET `?uploads` | 孤儿 uploadId 清理 |
| `presignGet` 增强 | extraQuery | 解压 Range / 分享 / 下载 disposition |

### 1.3 IndexedDB v2（`files/search-index.ts` 的 MetaStore 同库扩展）

- DB `mmagic-search` 升 version 2，新增 store **`uploads`**（keyPath `fingerprint`）——断点续传 checkpoint。
- **shares 不入库**：分享真源即桶内 `shares/` 前缀对象，管理台直接 ListObjectsV2——零双写、零同步问题。

### 1.4 能力开关与 i18n 挂点

- JSSDK 命令级开关走既有 `commands.ts` features 通道：新增 `restore` / `purge` / `share` / `unzipExtract` 命令注册（宿主可关）。
- `config/features.ts` 的 FeatureKey 不动（那是 dev/实验开关，不混用）。
- i18n：`share.pw.*` / `share.manage.*`、`files.trash.*`、`transfer.checkpoint.*`、`unzip.*`，中英同增。

## 2. 断点上传（M2）——对齐 OSS 断点续传

### 2.1 大厂对标

| 厂商 | 机制 | 关键参数 | 跨会话续传介质 |
|---|---|---|---|
| AWS S3 | Multipart Upload | 分片 5MB~5GB（末片除外），≤10000 片，对象上限 5TB；uploadId 存活至 complete/abort | 自管（SDK 层） |
| [阿里云 OSS](https://help.aliyun.com/zh/oss/user-guide/multipart-upload) | 分片 + [断点续传](https://help.aliyun.com/zh/oss/user-guide/resumable-upload) | 分片 100KB~5GB，≤10000 片，≤5TB；>100MB 官方建议走断点续传 | **Checkpoint 文件** |
| Google Drive | Resumable session URI | `308 Resume Incomplete`，`Range: bytes=0-0` 探进度，session ≈1 周有效 | session URI |
| Dropbox | upload session append/finish | 会话式追加 | session id |
| tus 协议 | PATCH + Upload-Offset | 旁证标准形态 | offset 协商 |

### 2.2 需求细节（对齐 OSS checkpoint 模式）

| # | 需求 | 细节 |
|---|---|---|
| F1 | **跨会话断点续传** | IDB `uploads` 表存 checkpoint：`{ fingerprint=sha256(path:size:lastModified), path, size, lastModified, partSize, uploadId, parts:[{number,etag}], createdAt, updatedAt }`。入队即写、每片成功即更、complete/abort/失败终态删除。应用启动检出未完成行 → 顶栏面包条「继续上次上传」→ `ListParts` 探活 uploadId：有效→resume 只补缺失片；`NoSuchUpload`（已过期/被清）→ 整件重传 |
| F2 | **单片自动重试** | 每片独立重试 3 次，退避 500ms→1s→2s + 抖动；403/凭证过期 → `setCredentials()` 热换后重签重试；4xx 语义错不重试直接 fail |
| F3 | **自适应分片** | `partSize = max(8MB, pow2ceil(size/10000))`——保证 ≤10000 片（S3/OSS 硬约束），大文件自动增大分片，5TB 天花板（产品层仍受宿主 `uploadMaxBytes` 约束） |
| F4 | **进度上报** | multipart 按「完成片×partSize」精确累加，`onProgress(bytes, total, rate)` → UploadPanel 显示百分比+MB/s。单 PUT 直传（≤16MB 阈值）受 fetch 限制无精细进度——文档注明，阈值以上才有 |
| F5 | **孤儿 uploadId 清理** | 启动时 `listMultipartUploads()` → 初始化时间 >7 天 → `abortMultipart`（对齐 S3 lifecycle `AbortIncompleteMultipartUpload` 7 天建议），结果静默；文档同时给出桶端 lifecycle 配置作服务端兜底 |
| F6 | **分片完整性** | 现状已带 `x-amz-checksum-crc32`（`client.crc32Base64`）——保持；对齐 OSS 分片 CRC 校验 |

### 2.3 边界与失败面

- 刷新/断网/杀进程：checkpoint 已落 IDB，恢复不重传已完成片（OSS 语义）。
- 同文件同路径重复上传中断件：fingerprint 相同 → 复用同一 uploadId 续传。
- 桶端已 abort / uploadId 过期：探活失败 → 整件重传，不报死错。
- 明确**不做：秒传**（hash 预检秒传需服务端 hash 索引，破红线；百度/百度企业版形态无法纯前端复刻）。

### 2.4 验收标准

1. 上传 >32MB 文件中途刷新页面 → 重开后恢复提示 → 续传且已完成片不重传（Network 断言）。
2. 断网第 3 片 → 单片重试 3 次后进失败态 → 恢复网络 retry 成功。
3. 大文件分片自适应：≥1TB 级虚拟 size（按公式计算，不必真传）→ partSize 自动放大且总片数 ≤10000；1GB 文件按公式=基础 8MB（≤10000 片天然满足）。
4. 手工制造孤儿 uploadId（SDK 直调）→ 重启后 7 天外被自动 abort。
5. 上述各一条 vitest 单测 + 一条 MinIO 真桶 E2E（`test-report/` 证据链）。

## 3. 回收站（M3）——对齐 Drive / OneDrive / Dropbox

### 3.1 大厂对标（保留期）

| 服务 | 保留期 | 备注 |
|---|---|---|
| [Google Drive](https://ask.revolgy.com/en/support/solutions/articles/11000095279-google-drive-trash-time-limit) | **30 天** | 2020-10-13 起自动清空（此前无限期） |
| OneDrive 个人 | 30~93 天 | 3 天起、最长 93 天（视清理压力） |
| OneDrive 企业 | **93 天** | SharePoint 两级站（63+30） |
| [Dropbox](https://blog.keeply.work/en/post/dropbox-recover-deleted-30-days) | 30 天 / 付费 **180 天** | 180 天档与 Rewind 绑定 |
| 百度网盘 | 10 天 | 会员可延长 |
| **本方案** | 建议 30 天 | 桶端 lifecycle 兜底（见 3.3） |

### 3.2 需求细节

| # | 需求 | 细节 |
|---|---|---|
| F1 | **前置检测与引导** | `getBucketVersioning()` → 未开启：回收站入口显示引导页（含 `mc version enable` / `s3api put-bucket-versioning` 命令 + 复制按钮 +「重新检测」）；开启：正常进入。MinIO 完整支持 versioning |
| F2 | **删除即入站** | 现有 `remove`（DeleteObjects 批量）**零改动**——桶开 versioning 后 DELETE 自动生成 DeleteMarker（latest），文件从列表消失=进站。既有 UI/JSSDK 语义自然升级 |
| F3 | **回收站视图** | `TrashPanel.vue`（左栏 nav 入口）：`listObjectVersions` 按 key 分组，**latest 为 DeleteMarker 的 key = 已删项**；列 原路径/删除时间（marker LastModified）/历史版本数/大小；`key-marker` 分页 |
| F4 | **恢复** | `deleteVersion(key, markerVersionId)`（删 DeleteMarker）→ 旧版本复现=恢复；批量恢复并发 3；树/列表即时回流 |
| F5 | **彻底删除** | 该 key 全部 versions+markers 逐个 `deleteVersion`；红色确认「不可恢复」；shift+del 快捷路径 |
| F6 | **清空回收站** | 遍历全部已删 key 执行 F5，进度条 + 可取消 |
| F7 | **恢复冲突** | 版本链语义天然无冲突（恢复=去 marker，latest 回到最近实体版本）；仅当链路复杂（删后又覆盖）时 UI 展示版本链让用户选择 |
| F8 | **版本历史（P1 顺带，versioning 白送）** | 文件右键「历史版本」→ 该 key 全版本列表 → 预览/下载/恢复任意版本——**三家竞品均无此能力**（对比表差异化项） |

### 3.3 技术设计与保留期

- 自动过期纯前端不可为（PutBucketLifecycle 属管理面）→ 引导页给桶端配置：
  ```bash
  mc ilm rule add myminio/mmagic-demo --noncurrent-expire-days 30   # MinIO
  # S3: Lifecycle Rule → NoncurrentVersionExpiration 30d
  ```
  UI 显示「建议保留 30 天（桶端 lifecycle 配置）」；未配置时条目不过期，仅提示。
- 风险：versioning 开启后旧版本累积、存储翻倍 → lifecycle 兜底 + 引导页明示；对嵌入方输出「开启 versioning 的容量代价」说明模板。

### 3.4 验收标准

1. 引导页：未开 versioning 桶显示命令+复制；开启后重检通过。
2. 删除文件 → 回收站出现（路径/时间正确）→ 恢复 → 树回流且内容完整。
3. 彻底删除后 `listObjectVersions` 该 key 零版本。
4. 覆盖写 3 次再删除 → 版本历史显示 3 个实体版本 + marker，恢复任一版本生效。
5. 批量恢复/清空进度可取消；features 通道关 `restore` 后 JSSDK 拒绝。

## 4. 在线解压（M4）——对齐百度/阿里云盘

### 4.1 大厂对标

| 能力 | 百度网盘 | 阿里云盘 | 本方案 |
|---|---|---|---|
| zip/rar 云解压 | ✓ / ✓ | ✓ / ✓ | zip ✓（rar 不做，见 4.4） |
| 7z | ✗ | ✗* | ✗ |
| 压缩包内**预览浏览** | ✓ | ✓ | ✓（Range 只读中心目录，秒开） |
| 分卷压缩包 | ✗ | 受限 | ✗（识别并提示） |
| 加密压缩包 | 受限 | 受限 | ✗（识别 🔒 并提示下载本地解压） |

> 百度行为佐证：[知乎·百度网盘 7z 解压讨论](https://www.zhihu.com/question/267029168)、[云解压进度与限制](https://www.zhihu.com/question/420926736)——「分卷不支持、带密码压缩包受限」是行业通行边界，本方案对齐而非超越。

### 4.2 需求细节

| # | 需求 | 细节 |
|---|---|---|
| F1 | **压缩包浏览** | 双击 zip → 内置应用 `zip-browser`（`apps/renderers/`）：条目表（名称/大小/压缩后/修改时间/方法）+ 路径树 + 勾选。**只读 EOCD+中心目录**（Range 尾部 ~64KB 起，千字节级流量）→ 大包秒开 |
| F2 | **选择性解出** | 勾选 →「解出到 `<zip名>/`」→ 逐条 Range 读 local header+压缩数据 → fflate `inflateRaw`（method 0 store / 8 deflate）→ CRC32 校验（复用 client crc32 工具）→ 入 upload-queue 上传回桶（复用 multipart/onConflict 冲突策略） |
| F3 | **整体解压 / 仅下载** | 全选=整体解压；「下载」打包本地 zip（复用 zip.ts，受 256MB 闸） |
| F4 | **文件名编码** | general purpose bit 11=UTF-8；无 flag → `TextDecoder('utf-8',{fatal:true})` 严格解码，失败回退 `TextDecoder('gbk')`（Windows 中文压缩包生态，对齐国内行为） |
| F5 | **zip64** | sizes/offset 出现 0xFFFFFFFF/0xFFFF → extra field 0x0001 取真实值；EOCD 定位含 zip64 locator（PK\x06\x07）+ zip64 EOCD（PK\x06\x06）；>4GB 压缩包可浏览可解压（下载仍受 256MB 打包闸） |
| F6 | **加密包行为** | 中心目录 flag bit 0 = 加密 → 条目标 🔒，顶部提示「加密压缩包不支持在线解压，请下载后本地解压」（对齐百度「受限」行为，明确优于报错） |
| F7 | **解压炸弹防护** | 总解压大小 ≤2GB（`unzipMaxBytes` embed 可配）、条目数 ≤10000、单条压缩比 >200 拦截；超限 toast 拒绝 |
| F8 | **zip slip 防护** | 条目名含 `..` 段/绝对路径/盘符 → 拒绝该条目并标红——解出路径一律 `normalize` 后校验前缀 |

### 4.3 技术要点

- Range 读走 `presignGet(key, {extraQuery})` + `Range:` 头（不参与签名，M1 后零障碍）；`If-Range` 不需要（对象版本内字节不变）。
- 解析器独立纯函数模块 `src/files/zip-reader.ts`（EOCD 定位/中心目录解析/local header 读取），**全部可单测**（fixture zip 二进制入库）。
- 前置闸：`maxBytes`（如 512MB）超限不允许浏览（防 Range 滥用），提示走下载。

### 4.4 明确不做

- **rar**：UnRAR 专有授权条款（免费自用但禁逆向重构）——与 pptx-preview 授权红线同类，不引。
- **7z**：无成熟轻量纯 JS 解码器（LZMA SDK 体积/维护差），百度也不支持，不追。
- **分卷**：识别 `.z01/.zip.001` 并提示「分卷压缩包不支持在线解压」。
- **tar/tar.gz**：P2 顺手项（fflate 有 gunzip，ustar 解析极简，择机）。

### 4.5 验收标准

1. 200MB zip（含中文 GBK 文件名 + 子目录 + 空目录）→ 秒开浏览、名称不乱码、选择性解出 3 个文件内容逐字节一致（CRC 通过）。
2. zip64 包（>4GB 稀疏 fixture 或构造 header）→ sizes 正确可浏览。
3. 加密 zip → 🔒 标记 + 提示文案；含 `../evil` 条目的恶意 zip → 条目被拒且 E2E 断言桶内无越前缀对象。
4. 超 2GB 声明解压总量的包 → 拦截 toast。

## 5. 分享增强（M5）——对齐 Dropbox / Box / 百度网盘

### 5.1 大厂对标

| 能力 | [Dropbox](https://help.dropbox.com/share/set-link-permissions) | [Box](https://docs.box.com/en/box-fundamentals/for-users/collaborating/using-shared-links/configuring-individual-shared-link-settings) | OneDrive | 百度网盘 | 本方案 |
|---|---|---|---|---|---|
| 密码 | ✓（Family 档无） | ✓ | ✓ | 提取码 4 位 | ✓ 6 位（可自定） |
| 有效期 | ✓ | ✓（到期自动禁用） | ✓ | 7 天档 | ✓ 1h/24h/7d/自定义（≤7d） |
| 下载次数硬限制 | ✗ | ✗ | ✗ | ✓（可设） | ✗ 纯前端不可记账 → provider 扩展点 |
| 禁止下载（仅预览） | — | ✓ | ✓（阻止下载） | — | P2（预览形态已有体系） |
| 真撤销（闸门在服务端） | ✓ | ✓ | ✓ | ✓ | 撤销=删 meta（≤签名时效窗口，见 5.2） |
| 分享管理台 | ✓ | ✓ | ✓ | ✓ | ✓（`shares/` 前缀即索引） |

> 对标发现：**Dropbox/Box 原生均无下载次数硬限制**（仅百度系有）——次数需求烈度低于预期，且纯前端无法由访问者写回计数（访问者无凭证）。方案：`ShareStatsProvider` 接口宿主注入（对齐 recentProvider 模式），无 provider 隐藏次数选项，P2。

### 5.2 威胁模型与关键设计论证（本能力核心）

纯前端根本约束：**访问者会话没有 S3 凭证**，SigV4 预签名上限 **604800s（7 天，`AWS_MAX_PRESIGN_EXPIRES_SEC` 已有常量）**。要让访问者下载，签名 URL 必须在链接或可读对象里——由此推导出「**密码信封**」方案：

- 访问页拿到的是 shareId + **meta 对象**（`shares/<shareId>.json`，其读取用内嵌的 meta 预签名 URL，随链接走）。
- meta 内**不含明文签名 URL**，存的是 `AES-GCM-256(密钥=PBKDF2-SHA256(密码, salt, 10万轮), 明文=对象预签名 GET URL)` 的密文 + KDF 参数。
- **密码校验=解密成功**：GCM auth tag 保证错密码必然解密失败——无需单独存 hash，无哈希可比对攻击面。
- 只拿到 meta 读权限/半截链接的人，拿不到任何可用签名——密码真正守住了门。

诚实边界（写入 UI 与文档）：

1. **永久分享天花板 = 7 天**（SigV4 硬上限；大厂永久分享靠后端闸门）。到期前校验页显示「分享已到期」。
2. **撤销窗口**：删 meta 对象 → 校验页 404「分享已取消」，**但已解密拿到签名 URL 的人在签名有效期内仍可下载**——「重置分享」=换 shareId 重发；真撤销需后端，不做。
3. **密码错误次数限制**只能本地节流（错 5 次锁 30s），技术动机者可绕过——标注即可。

### 5.3 需求细节

| # | 需求 | 细节 |
|---|---|---|
| F1 | **创建分享（密码信封）** | ShareDialog 增强：密码开关（默认随机 6 位、可自定）、有效期 1h/24h/7d/自定义日期（≤7d 上限置灰）、生成 → `PUT shares/<shareId>.json`（shareId=`crypto.getRandomValues` 16B base64url 22 字符不可枚举）→ 展示 **链接+密码同框复制**（对齐百度「链接+提取码」交互习惯） |
| F2 | **校验页** | 公开路由 `/s/:shareId`（免 embed config；endpoint/bucket 走链接 hash `#m=<metaURL>` 防进 server log）：密码框 → 解密 → 成功后复用预览体系展示 + 下载按钮 |
| F3 | **过期双闸** | meta.expiresAt（UI 先拦）+ 预签名到期（S3 硬拦）——绕过 UI 也过不了签名 |
| F4 | **撤销** | 「我的分享」里删除 meta 对象 → 校验页 404 |
| F5 | **分享管理台** | ShareDialog「管理」Tab：`ListObjectsV2(prefix=shares/)` → 目标/创建/到期/复制/撤销；不需要任何本地索引（真源在桶） |
| F6 | **次数（P2）** | `ShareStatsProvider` 宿主注入，有则校验页展示剩余次数 |
| F7 | **仅预览分享（P2）** | meta.allowedOps 驱动校验页隐藏下载按钮（软限制，防君子） |

### 5.4 meta 对象形态（契约）

```jsonc
// shares/<shareId>.json
{
  "v": 1, "key": "docs/report.pdf", "name": "report.pdf", "size": 102400,
  "createdAt": 1730000000000, "expiresAt": 1730604800000,
  "kdf": { "alg": "PBKDF2-SHA256", "iterations": 100000, "salt": "<b64>" },
  "blob": "<AES-GCM-256 ciphertext b64>", "iv": "<gcm iv b64>"
  // blob 明文 = 对象预签名 GET URL（expires = 分享时效）
}
```

WebCrypto 全链（`deriveBits`/`encrypt`）纯浏览器可用，新模块 `src/files/share-crypto.ts` 纯函数可单测。

### 5.5 验收标准

1. 带密码分享 → 无密码打开校验页被拦；正确密码 → 预览+下载成功；错误密码 5 次触发本地锁定。
2. meta 对象直读（手工 GET）→ 只有密文，无密码提不出签名 URL（安全断言）。
3. 24h 分享 → 系统时间跨过期（mock）后校验页显示到期；撤销 → 校验页 404。
4. 管理台列出全部分享且撤销/复制可用；features 关 `share` 后入口与命令均拒绝。

## 7. 工程纪律（延续 v1.1 门禁）

- 新模块一律纯函数先行（zip-reader/share-crypto/checkpoint）→ vitest 单测；**全局行覆盖 ≥80% 门禁不回退**。
- 每能力一条 MinIO 真桶 E2E 入 `test-report/` 证据链；versioning/lifecycle 用 demo 桶实测（含开/关两态）。
- 契约变更（meta 形态、checkpoint schema、features 命令）同步 `docs/design/jsdk-api.md`。

## 8. 明确不做（红线，竞品有但放弃）

秒传（需服务端 hash 索引）· 永久分享（SigV4 7 天天花板）· 下载次数硬限制（无服务端记账；provider 交宿主）· 真撤销闸门 · rar/7z/分卷解压 · 服务端解压/转码。
